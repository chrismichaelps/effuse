# Security model — `@effuse/auth`

Every mitigation below has a regression test that names the attack. Where a
control is absent or partial, this document says so plainly — a security page
that only lists wins is a marketing page.

## What this package defends against

| Attack                                         | Mitigation                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Test                                                                                                                           |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Session fixation                               | The session identifier is regenerated on every privilege change. `signIn` always mints a fresh id and never adopts one the caller arrived with.                                                                                                                                                                                                                                                                                                                   | `session-engine.test.ts` → _session fixation_; `entrypoints.test.ts` → _issues a distinct session id per sign-in_              |
| Sibling-subdomain cookie overwrite             | `__Host-` cookie prefix whenever the configuration qualifies. The browser then enforces `Secure`, `Path=/`, and no `Domain`, so a subdomain cannot overwrite the session cookie. An explicit but ineligible prefix request fails at configuration time; an omitted prefix truthfully defaults off when `Domain`, a non-root path, or insecure local transport makes it ineligible.                                                                                | `cookies.test.ts` → _applies the `__Host-` prefix_; `resilience.test.ts` → _explicit host-prefix settings_                     |
| Token forgery                                  | HMAC-SHA256 with a fixed algorithm. Tokens carry no header, so there is no algorithm field to lie in — this closes `alg: none` and RS256→HS256 confusion by construction.                                                                                                                                                                                                                                                                                         | `token-codec.test.ts` → _forgery resistance_                                                                                   |
| Timing attacks on signature comparison         | Both sides are hashed to a fixed width and compared with `timingSafeEqual`. Normalising the length matters: `timingSafeEqual` throws on a length mismatch, and catching that throw would itself be a timing signal.                                                                                                                                                                                                                                               | `token-codec.test.ts`, `csrf.ts`                                                                                               |
| Base64 malleability                            | The payload must match the strict base64url alphabet and survive a re-encode round-trip. Node's decoder is lenient, and two distinct strings decoding to one payload is a signature-bypass primitive.                                                                                                                                                                                                                                                             | `token-codec.test.ts` → _malformed input_, _valid base64 but not a JSON object_                                                |
| Replay after sign-out                          | Stateful sessions are deleted server-side. Stateless sessions **with a store** are equally revocable: the store is authoritative on liveness, so a missing record means revoked and a destroyed token cannot resurrect itself from its own payload.                                                                                                                                                                                                               | `session-engine.test.ts` → _revocation_                                                                                        |
| Cookie rotation races                          | A rotated-away session is marked superseded rather than deleted. For a bounded overlap window a request still carrying the old token resolves to the successor and is handed a replacement cookie, so concurrent rotations converge instead of signing the user out.                                                                                                                                                                                              | `session-engine.test.ts` → _rotation races_                                                                                    |
| Unbounded session lifetime                     | Separate idle and absolute timeouts. Absolute expiry is measured from creation, is carried across rotation unchanged, and cannot be extended by activity — so a stolen token has a hard ceiling.                                                                                                                                                                                                                                                                  | `session-engine.test.ts` → _enforces the absolute lifetime_, _does not extend absolute expiry across a rotation_               |
| Oversized-cookie silent loss                   | Values beyond the ~4 KB browser cap are split into numbered chunks, measured on the percent-encoded byte length rather than character count.                                                                                                                                                                                                                                                                                                                      | `cookies.test.ts` → _chunking_                                                                                                 |
| Stale chunks after a shrink                    | Clearing is driven by the chunks the request actually carried, not by what the current value would occupy. A leftover trailing chunk would otherwise make every later read fail permanently.                                                                                                                                                                                                                                                                      | `cookies.test.ts` → _expires every chunk currently present_                                                                    |
| Cookie shadowing                               | Duplicate cookie names resolve first-wins. Browsers send the more specific cookie first, so an attacker appending a value from a parent domain does not win.                                                                                                                                                                                                                                                                                                      | `cookies.test.ts` → _keeps the first occurrence when a name repeats_                                                           |
| CSRF                                           | Signed, session-bound, expiring double-submit token. The session id is inside the signed message, so a token minted under an attacker's own account cannot be spent against a victim. Unsafe methods are an allowlist, so an unrecognised verb is challenged rather than waved through.                                                                                                                                                                           | `csrf.test.ts`                                                                                                                 |
| User enumeration                               | An unknown identifier is verified against a dummy hash produced by the configured hasher, so both paths do the same work. Both return `InvalidCredentialsError` with an identical `safeMessage`.                                                                                                                                                                                                                                                                  | `credentials.test.ts` → _user enumeration_, including a statistical timing-parity assertion                                    |
| Lockout evasion by identifier casing           | Identifiers are normalised and compared case-insensitively, so `A@example.com` cannot bypass a lock on `a@example.com`.                                                                                                                                                                                                                                                                                                                                           | `credentials.test.ts` → _matches the identifier case-insensitively_                                                            |
| Brute force                                    | Account lockout after a configurable threshold, reported with `retryAfterMs`.                                                                                                                                                                                                                                                                                                                                                                                     | `credentials.test.ts` → _brute force_                                                                                          |
| Lockout as a denial-of-service tool            | Per-identifier and per-IP rate-limit budgets are independent. A shared budget would let an attacker exhaust a victim's allowance from anywhere and lock them out without guessing anything.                                                                                                                                                                                                                                                                       | `credentials.test.ts` → _keeps per-identifier and per-IP budgets independent_                                                  |
| Offline cracking of stolen hashes              | scrypt at OWASP's current floor (N=2^17, r=8, p=1) by default, per-hash salt, parameters recorded in the stored hash so cost can be raised later without a migration.                                                                                                                                                                                                                                                                                             | `password-hasher.test.ts`                                                                                                      |
| Memory exhaustion via a tampered hash row      | Verification takes its work factor from the stored hash, so a ceiling is enforced before any derivation is attempted.                                                                                                                                                                                                                                                                                                                                             | `password-hasher.test.ts` → _rejects parameters large enough to exhaust memory_                                                |
| Foreign or corrupted hashes frozen in place    | `needsRehash` returns `true` for anything unparseable, so such records are replaced at the next successful sign-in rather than trusted forever.                                                                                                                                                                                                                                                                                                                   | `password-hasher.test.ts` → _flags an unparseable hash_                                                                        |
| Prototype pollution from decoded payloads      | `__proto__`, `constructor`, and `prototype` are rejected in claims and cookie names; decoding builds on a null-prototype object and copies only declared keys.                                                                                                                                                                                                                                                                                                    | `claims.test.ts` → _rejects prototype-polluting keys_; `cookies.test.ts` → _ignores prototype-polluting cookie names_          |
| Claim smuggling                                | Undeclared keys are dropped rather than passed through, and values are type-checked rather than coerced.                                                                                                                                                                                                                                                                                                                                                          | `claims.test.ts` → _drops unknown keys_, _rejects a claim of the wrong type_                                                   |
| Denial of service via malformed input          | Token verification, cookie parsing, CSRF verification, and password verification all return a failure value instead of throwing. These parse fully attacker-controlled input on every request; a throw would be an unhandled 500.                                                                                                                                                                                                                                 | `token-codec.test.ts`, `cookies.test.ts`, `csrf.test.ts`, `password-hasher.test.ts`                                            |
| Backend outage becoming an unhandled rejection | Every store call is routed through `StoreError` on the typed channel. A connection reset surfaces as a decision the caller can make, not a stack trace. Sign-out degrades to clearing the cookie rather than erroring at a user who has already decided to leave.                                                                                                                                                                                                 | `resilience.test.ts` → _backend failures_                                                                                      |
| Backend error text reaching a client           | The backend's own message — frequently containing a connection string — is confined to `detail`, which `toSafeResponseInit` never reads.                                                                                                                                                                                                                                                                                                                          | `resilience.test.ts` → _keeps the backend message out of anything client-visible_                                              |
| Corrupted or hand-edited session records       | Records returned by a store are shape-validated before use. `null` from a JSON column reads as "signed out"; a malformed record fails its own request as a `StoreError` rather than propagating half-typed values into a policy.                                                                                                                                                                                                                                  | `resilience.test.ts` → _corrupted store records_                                                                               |
| Silent privilege drift across a deploy         | A session missing a newly required claim fails closed with `InvalidTokenError` rather than being handed over with the field undefined. Adding the claim as `optional()` is the no-downtime migration path.                                                                                                                                                                                                                                                        | `resilience.test.ts` → _schema evolution_                                                                                      |
| Unbounded index growth                         | The subject index is pruned on destroy and never double-indexes a session rewritten by idle-window slides, so `signOutEverywhere` stays a keyed lookup rather than degrading into a scan.                                                                                                                                                                                                                                                                         | `resilience.test.ts` → _storage-backed store housekeeping_                                                                     |
| Password trimming shrinking the keyspace       | Identifiers are trimmed; passwords never are. Leading and trailing spaces are legitimate password characters.                                                                                                                                                                                                                                                                                                                                                     | `resilience.test.ts` → _does not trim the password_                                                                            |
| Reset-token database disclosure                | Reset links carry 256 random bits and persistence receives only a SHA-256 digest. A database reader cannot redeem the stored value; the raw bearer exists only at issuance and in the side-channel link.                                                                                                                                                                                                                                                          | `password-reset.test.ts` → _persists only a digest_                                                                            |
| Reset replay and concurrent redemption         | `PasswordResetStore.consume` is an atomic port operation held to an executable conformance suite. Exactly one concurrent caller wins, replacement revokes the older link, and expiry is enforced at the exact boundary.                                                                                                                                                                                                                                           | `password-reset.test.ts` → _concurrent redemption_; `conformance.test.ts` → _PasswordResetStore conformance_                   |
| Password reset leaving stolen sessions alive   | Successful redemption revokes every session for the subject and emits a required completion event for the application's durable security-notification outbox. It does not auto-login or erase failed-authentication history.                                                                                                                                                                                                                                      | `password-reset.test.ts` → _updates the password, preserves failed-auth state, revokes sessions, and emits an event_           |
| Password-reset probing and inbox flooding      | Issuance is throttled independently by subject and client address; redemption is throttled by address. The library begins after subject resolution so it cannot accidentally choose a distinct unknown-account response. The application must keep response text and timing uniform.                                                                                                                                                                              | `password-reset.test.ts` → _rate-limits repeated issuance_, _rate-limits token verification_                                   |
| Weak or duplicate rotation secrets             | Every signing secret under 32 characters and every duplicate rotation entry is rejected by `defineAuth`, before lower-level codecs or request traffic. A weak fallback still compromises captured tokens, while duplicate entries create the appearance of rotation without changing key material.                                                                                                                                                                | `resilience.test.ts` → _weak signing secret_, _duplicate rotation secrets_; `token-codec.test.ts` → _configuration validation_ |
| Cookie metadata injection                      | `defineAuth` accepts only unprefixed HTTP-token names, absolute paths without controls or semicolons, and normalized bare ASCII hostnames. Schemes, ports, paths, malformed DNS labels, and overlong domains fail with a path-specific configuration error before a response is emitted.                                                                                                                                                                          | `resilience.test.ts` → _unsafe cookie name_, _unsafe cookie path_, _unsafe cookie domain_                                      |
| Forced sign-out on secret rotation             | Ordered secret list: the first signs, all verify. Rotation is a two-deploy operation with no session loss.                                                                                                                                                                                                                                                                                                                                                        | `token-codec.test.ts` → _secret rotation_                                                                                      |
| Server crypto in the client bundle             | `@effuse/auth/client` and the isomorphic root are asserted to reach no `node:` builtin, by walking the actual import closure.                                                                                                                                                                                                                                                                                                                                     | `entrypoints.test.ts` → _client bundle purity_                                                                                 |
| Session data leaking into HTML                 | Claims are `expose: false` opt-out, and `exposedClaims` is the only projection the hydration path uses.                                                                                                                                                                                                                                                                                                                                                           | `claims.test.ts` → _omits claims not marked for exposure_                                                                      |
| Authorization-code interception                | PKCE with S256 is mandatory. `plain` and every unrecognised method are refused with no fall-through, so a downgrade cannot be negotiated. A provider that does not advertise S256 support is refused at `start`.                                                                                                                                                                                                                                                  | `oauth-pkce.test.ts`; `oauth-flow.test.ts` → _pkce enforcement_                                                                |
| Login CSRF via a planted callback              | The state id also travels in an HttpOnly cookie, and the callback requires both to be present and equal. The `state` parameter alone only proves a callback matches _a_ flow we started, not one _this browser_ started — which is what lets an attacker hand a victim their own callback URL.                                                                                                                                                                    | `oauth-flow.test.ts` → _login CSRF_                                                                                            |
| Callback replay                                | The stored flow record is single-use and consumed before anything else can fail, so a replayed callback finds nothing even when the first attempt errored.                                                                                                                                                                                                                                                                                                        | `oauth-flow.test.ts` → _replay_                                                                                                |
| ID token forgery                               | Signature verified before any claim is read. Key type checked against the algorithm family.                                                                                                                                                                                                                                                                                                                                                                       | `oauth-id-token.test.ts` → _signature forgery_                                                                                 |
| `alg: none`                                    | A signature-free token is rejected before any comparison, and `none` is in no allowlist.                                                                                                                                                                                                                                                                                                                                                                          | `oauth-id-token.test.ts` → _rejects a token with no signature at all_                                                          |
| RS256-to-HS256 confusion                       | HMAC algorithms are never permitted for ID tokens, and key material is an asymmetric `KeyObject` that cannot serve as an HMAC secret. The header's `alg` is checked against provider metadata; it never selects the routine.                                                                                                                                                                                                                                      | `oauth-id-token.test.ts` → _rejects an HMAC algorithm_                                                                         |
| ID token replay                                | `nonce` is required whenever one was sent, and a token that omits the claim is rejected rather than skipping the check.                                                                                                                                                                                                                                                                                                                                           | `oauth-id-token.test.ts` → _replay protection_                                                                                 |
| Token substitution                             | `aud` must contain this client; with multiple audiences `azp` must name it. `at_hash` binds the ID token to the access token issued with it.                                                                                                                                                                                                                                                                                                                      | `oauth-id-token.test.ts` → _claim validation_                                                                                  |
| Mix-up attacks                                 | When the provider echoes `iss` (RFC 9207) it must match the one that started the flow, so a code from one issuer cannot be redeemed at another. Absence is tolerated; a mismatch is not.                                                                                                                                                                                                                                                                          | `oauth-flow.test.ts` → _mix-up_                                                                                                |
| Open redirect after sign-in                    | Targets are resolved through the URL parser and checked by origin against an allowlist, then re-validated on the way out. Covers protocol-relative, backslash, userinfo, control-character, and lookalike-suffix forms.                                                                                                                                                                                                                                           | `oauth-redirect.test.ts`                                                                                                       |
| Discovery pointing elsewhere                   | The document's own `issuer` must match the one requested, and every endpoint must be https. Otherwise the document redirects the key fetch itself to an issuer nobody chose.                                                                                                                                                                                                                                                                                      | `oauth-flow.test.ts` → _discovery_                                                                                             |
| JWKS fetch amplification                       | Refetch on an unknown `kid` is rate-limited and concurrent fetches collapse into one, so forged tokens with random key ids cannot be turned into traffic against the provider. A plaintext JWKS endpoint is refused outright.                                                                                                                                                                                                                                     | `oauth-id-token.test.ts` → _jwks resolver_                                                                                     |
| Account takeover via unverified email          | Automatic linking is not performed by this package at all. `emailVerified` is surfaced on the callback result so the decision is explicit, and `standardProfile` requires `email_verified === true` rather than coercing a truthy value.                                                                                                                                                                                                                          | `oauth-flow.test.ts` → _reports whether the provider asserts the email is verified_                                            |
| Refresh stampede signing users out             | Concurrent refreshes collapse via an in-process promise map and a store-backed cross-process lock, so a page load's worth of requests produces exactly one upstream redemption. Without this every request redeems the same refresh token, the provider invalidates it on first use, and the user is signed out with nothing in any log explaining why.                                                                                                           | `oauth-refresh.test.ts` → _single flight_                                                                                      |
| Stale token presented after losing the lock    | The record is re-read **after** the lock is acquired, not before. A replica that refreshed in the gap would otherwise leave us presenting an already-redeemed token, drawing `invalid_grant` and tearing down a healthy session — reintroducing the bug the lock exists to prevent.                                                                                                                                                                               | `oauth-refresh.test.ts` → _re-reads the record after taking the lock, not before_                                              |
| Wedged session from a crashed refresher        | The lock carries a TTL, so a process dying mid-refresh frees it rather than blocking the session indefinitely. Waiters have a bounded timeout and a typed failure instead of hanging.                                                                                                                                                                                                                                                                             | `oauth-refresh.test.ts` → _lock behaviour_                                                                                     |
| Refresh-token reuse                            | Tokens rotate on every redemption; the immediately-previous token stays valid for a bounded overlap so a retry after a lost response is not misread as theft, and anything older is reuse. `invalid_grant` tombstones the grant's rotation chain and emits an auditable event.                                                                                                                                                                                    | `oauth-refresh.test.ts` → _reuse detection_, _classifyRefreshToken_                                                            |
| Over-broad revocation                          | Deliberately **not** cascaded to the subject's other sessions. As a client, `invalid_grant` cannot distinguish theft from consent revoked upstream or plain expiry, and signing someone out of every device over an ambiguous signal is worse than the attack. Authorization servers, which can attribute reuse, use `classifyRefreshToken` and cascade themselves.                                                                                               | `oauth-refresh.test.ts` → _does not sign the subject out of their other sessions_                                              |
| Clock-race with the resource server            | Refresh fires a configurable margin before expiry (60s default) rather than at it, so the resource server never sees a token it considers expired.                                                                                                                                                                                                                                                                                                                | `oauth-refresh.test.ts` → _refreshes ahead of expiry by the skew margin_                                                       |
| Missing authorization check                    | Every route and method is enumerated from the compiled manifest with its effective policy. `assertPolicyCoverage` fails the build on an undeclared route, turning a forgotten check from an incident into a failed CI run. Scattered per-route conditionals cannot be audited at all — there is no list to compare against.                                                                                                                                       | `policy.test.ts` → _coverage audit_, _deny by default_                                                                         |
| Authorization bypass by method                 | Rules apply to every method unless they narrow explicitly, and coverage is reported per method — so a route whose GET is guarded and whose POST is not shows as one covered entry and one hole.                                                                                                                                                                                                                                                                   | `policy.test.ts` → _reports a route whose GET is guarded and whose POST is not_, _guards every method of a matched path_       |
| Silent widening of access                      | Overlapping rules combine with AND, so adding a rule can only narrow. Under most-specific-wins a new rule on a specific path silently widens what a broad rule guarded, and the diff only shows an addition. Overriding requires `override: true`.                                                                                                                                                                                                                | `policy.test.ts` → _rule combination_                                                                                          |
| Confused deputy                                | Policies receive the request context and are evaluated identically regardless of caller. There is no trusted-internal flag to set.                                                                                                                                                                                                                                                                                                                                | `policy.test.ts` → _evaluates internal and external callers identically_                                                       |
| Policy bug becoming a bypass                   | A predicate that throws denies. Failing open would turn any bug in a custom policy into an authorization bypass. Empty `all()` and `any()` deny rather than permitting vacuously.                                                                                                                                                                                                                                                                                 | `policy.test.ts` → _denies when the predicate throws_, _denies an empty any()_                                                 |
| Anonymous access through negation              | `not()` requires a session, so `not(claim('role','banned'))` cannot permit anonymous callers by trivially failing its inner policy.                                                                                                                                                                                                                                                                                                                               | `policy.test.ts` → _requires a session even under not()_                                                                       |
| Typo'd role silently denying everything        | Policy builders are bound to the claims declaration, so an unknown claim key or an out-of-union value is a compile error rather than a comparison that is always false — which looks identical to a working deny.                                                                                                                                                                                                                                                 | `policy.test.ts` → _type safety_                                                                                               |
| Probing via denial messages                    | `ForbiddenError` returns one opaque message regardless of which policy refused; the policy name lives in `detail`, which never reaches a response. 403 is distinguished from 401 so an authenticated user is not bounced to a sign-in page.                                                                                                                                                                                                                       | `policy.test.ts` → _produces a response whose body names no policy_                                                            |
| Session data leaking into HTML                 | Only claims left at the exposure default are serialised; `expose: false` claims and the subject never reach the page. The subject is omitted unconditionally — an internal user id is not needed to render, and shipping one by default is how identifiers reach analytics and error reports never scoped to hold them.                                                                                                                                           | `hydration.test.ts` → _payload projection_                                                                                     |
| XSS through the hydration payload              | The payload is an inert `<script type="application/json">` block, not a JavaScript assignment, so a claim value can never become code. `<` is escaped to `\u003C`, which closes both `</script>` in any casing and `<!--` while remaining lossless through `JSON.parse`. Choosing a non-executable block also removes the `U+2028`/`U+2029` class entirely — those are legal in JSON and terminate a JavaScript line, and mishandling them is a well-trodden XSS. | `hydration.test.ts` → _script injection_, nine hostile payloads                                                                |
| Client/server session drift                    | The server resolves the session once per request and writes it into the page; the client adopts that value and never fetches one of its own. There is no window in which the two can disagree because there is nothing to disagree with. This is the root of both the 49-reaction and 26-reaction bugs in the incumbent library.                                                                                                                                  | `hydration.test.ts` → _reading the payload_, _the invalidation channel_                                                        |
| Stale UI after sign-out                        | One invalidation channel: every subscriber updates from a single publish rather than polling. A listener that throws does not stop its peers — half a UI believing the user is still signed in is worse than one swallowed error.                                                                                                                                                                                                                                 | `hydration.test.ts` → _clears to anonymous on sign-out with no reload_, _keeps notifying peers when one listener throws_       |
| Blank page from a malformed payload            | Hydration falls back to the anonymous snapshot for anything unreadable rather than throwing. A throw here takes the application down before it starts; "looks signed out" is recoverable by a reload.                                                                                                                                                                                                                                                             | `hydration.test.ts` → _falls back to anonymous rather than throwing on malformed JSON_                                         |
| Client-side state used as enforcement          | The client module exposes only `current`, `subscribe`, `publish`, and `clear` — no signing, no verification, no way to mint a session. Documented as presentational only.                                                                                                                                                                                                                                                                                         | `hydration.test.ts` → _what the client is not_                                                                                 |
| Silent adapter divergence                      | All six ports — `SessionStore`, `RateLimiter`, `PasswordHasher`, `TokenCodec`, `UserStore`, `PasswordResetStore` — ship an executable conformance suite, covering lock exclusivity under real concurrency, TTL expiry, fencing, atomic reset consumption, value isolation, independent budgets, salting, and malformed-input behavior.                                                                                                                            | `conformance.ts`, exercised in `conformance.test.ts` against every reference implementation                                    |
| Untested authenticated paths                   | `createTestSession` issues a genuine signed session through the real engine, so authenticated and authorised routes are testable in three lines. A fixture that was a stub would prove only that a test double matches its author's assumptions.                                                                                                                                                                                                                  | `testing-kit.test.ts` → _produces a session the real engine accepts_, _is accepted by an independently constructed server_     |

## What this package does not do yet

These are tracked, not hidden. Do not assume coverage that has not shipped.

- **Plain OAuth 2.0 providers that issue no ID token** — GitHub being the obvious one — are not supported. They need a userinfo-based path that has not shipped; only OpenID Connect providers work today.
- **Account linking is not implemented.** The callback reports `emailVerified`; deciding whether to link is the application's call, and linking on an unverified email is an account-takeover vector.
- **Sibling-session revocation on password change** is available as `signOutEverywhere(subject)` but is not called automatically by `changePassword` — the two stores are independent ports and wiring them is the application's call.

## What the application still owns

Authentication does not make an application secure by itself. The application
and its deployment remain responsible for:

- TLS termination, HSTS, trusted-proxy configuration, and preventing plaintext
  traffic before it reaches the Effuse server.
- Secret storage, access control, rotation scheduling, and keeping secrets out
  of client bundles, logs, crash reports, and source control.
- XSS prevention in application output. HttpOnly protects the session cookie
  from direct reads, but injected script can still perform authenticated actions
  from the victim's browser.
- The correctness of custom authorization policies and the route manifest passed
  to `assertPolicyCoverage`. Coverage proves every route has a declaration; it
  cannot prove a business rule is the intended one.
- Identity lifecycle: registration, verified-email changes, account recovery,
  account linking, deletion, and administrative suspension.
- Password-reset delivery and HTTP presentation: uniform known/unknown account
  responses and timing, a trusted HTTPS origin rather than the request Host,
  `Referrer-Policy: no-referrer`, confirmation input, and completion email.
- Durable recovery operations: reset adapters fail closed after capability
  consumption, and the required completion hook should enqueue into a retried,
  monitored outbox rather than depend on inline email delivery.
- Abuse controls beyond sign-in, including endpoint rate limits, bot defence,
  anomaly detection, audit retention, and incident response.
- Dependency and platform patching, database isolation, backups, and restoring
  shared session/token storage without resurrecting revoked credentials.

Client hydration is never an authorization boundary. Hiding a control in the UI
does not protect its server route.

## Deliberately strict defaults

Loosen these only with a reason you would defend in review.

| Default                                          | Why it is strict                                                                                                                                | Cost of loosening                                                                                                                      |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Eligible cookies default to `hostPrefix: true`   | Stops sibling-subdomain cookie overwrite while keeping the resolved config truthful.                                                            | A `Domain`, non-root path, or insecure transport disables the implicit prefix; explicitly requesting an impossible prefix is rejected. |
| `cookie.secure: true`                            | Keeps the session off plaintext transports.                                                                                                     | Only disable for local `http` development.                                                                                             |
| `cookie.sameSite: 'lax'`                         | CSRF defence in depth.                                                                                                                          | `'none'` requires `Secure` and is rejected at config time otherwise.                                                                   |
| Minimum 32-character secrets                     | Below ~128 bits of entropy, a captured token is grindable offline.                                                                              | Rejected at construction; there is no override.                                                                                        |
| scrypt N=2^17                                    | OWASP's current floor.                                                                                                                          | Defaults are what most deployments run, so the default is the recommendation.                                                          |
| Password minimum length 12, no composition rules | Length correlates with strength; composition rules push people toward predictable substitutions, which is why current NIST guidance drops them. | —                                                                                                                                      |
| Absolute session lifetime 12 hours               | Bounds a stolen token.                                                                                                                          | Raising it raises the ceiling on undetected use of a stolen session.                                                                   |
